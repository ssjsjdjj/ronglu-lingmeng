v0.3.2修正了微信首次启动的空存档判断：`wx.getStorageSync` 返回空字符串或空白字符串时，按新玩家处理，避免被 `JSON.parse` 误报为损坏存档。新增回归检查覆盖空字符串、空白、null和undefined。

前13项继续覆盖基础交换、技能、连携、存档、损坏存档容错、切后台、触点标识、通关解锁、布局和模拟wx API启动清理。

新增7项覆盖：

1. 逐个创建1000关，每关验证初始棋盘无自动匹配、存在合法交换，冰晶格数与层数符合配置，再执行一次有效交换并检查棋盘稳定。
2. 后续关卡微光、收集和冰晶目标单调增加且有上界，守卫每10关出现，末期冻结周期正确。
3. 第6、20、500、700、1000关保存、恢复后，棋盘、随机数、守卫状态和下一操作结果一致。
4. 旧版五关存档迁移后保留星级、分数、角色、棋盘与重排次数，原第5关通关后能解锁第6关。
5. 第20、999、1000关的解锁边界；千关全部完成后显示完成文案，不访问不存在的第1001关。
6. 浏览50章、每章20关时，按钮保持在屏幕内，浏览锁定章节不会意外解锁关卡。
7. 已解锁第1000关时，可以从第50章选关并保存、恢复该关。

布局测试包含320×568、375×667、390×844、430×932和1920×1080。

模拟wx API测试使用接口桩，不能替代微信基础库、开发者工具实际编译或微信真机测试。

## 难度抽样

运行 `npm run check:balance`。使用固定种子，抽查第1、5、6、20、50、100、200、400、600、800、1000关，每关3局，共33局。策略使用砾石之约，逐步评估合法交换、可用技能和连携，选择目标收益较高的操作。

33局均找到通关路线。各阶段的平均有效交换数：

| 关卡 | 平均有效交换数 |
| --- | --- |
| 1 | 3.0 |
| 5 | 5.0 |
| 6 | 4.3 |
| 20 | 6.7 |
| 50 | 6.7 |
| 100 | 5.3 |
| 200 | 6.7 |
| 400 | 12.3 |
| 600 | 12.7 |
| 800 | 15.0 |
| 1000 | 23.3 |

第1000关的三局分别剩4、7、3步。这里的有效交换数不包含免费技能与连携。

模拟策略能查看一步操作的确定性结果，属于平衡诊断，不能当作真人通过率或1000关逐关通关证明。随机棋盘与守卫关会带来局部难度起伏；仍需收集真人试玩反馈继续调整。
